# 阈值调优 · 双门槛量化依据

> 本文档回答一个问题：**「分类概率 ≥ 60% 且 处理条件概率 ≥ 60%」这两个门槛为什么是这两个数字，以及怎么在数据变化后重新校准它们。**
>
> 数据基线：**v0.6（L3 补强 + chat 口径修正版）** · 230 条独立评估集（与训练集零重叠，含 22 条直播中断类）上的回放实测，
> 生成链路 `replay_eval.py → threshold_scan.py`，全部报告见 `backend/evals/reports/`。
> v0.2/v0.3 基线的同套扫描结论方向一致（见 git 历史）。

## 1. 双门槛体系的职责边界

```
模型（Laya 微调 + 分桶温度校准）          程序（routing.ts 阈值分流）
────────────────────────────            ─────────────────────────────
Choice: 类别 + 全候选概率分布     ──▶    classifyProbability = 0.60
Noul:   P(信息足够开始处理)       ──▶    actionableProbability = 0.60
Score:  0~3 优先级评分            ──▶    队列内排序（不参与门控）
```

- **模型负责给出概率**：温度校准之后，0.60 的语义是「这条弹幕的对象与诉求足以让助教开始处理」的置信度；
- **程序负责执行分流**：门槛是业务规则，不是模型属性——换模型、换判据、换场景，门槛都要重新量化；
- **人工兜底**：不满足门槛的消息进入「待确认」队列，由人工核对，不丢消息。

## 2. 为什么不能拍脑袋：三率三角

门槛调优本质是在三个比率之间找业务可接受的平衡：

| 比率 | 含义 | 过高/过低的影响 |
| --- | --- | --- |
| 完全自动正确率 | 判断正确且直接进对队列 | 越高自动化收益越大 |
| 进错队列率 | 类别判错但置信度/条件都过门槛 | 去错人，挫败感最强 |
| 漏处理/错放行率 | 该处理的被推到人工确认，或不该进的进了 | 人力成本 / 过度打扰 |

**课堂场景的业务偏好**：误进错误队列的挫败感 > 人工确认成本。所以本系统保留双门槛而非全自动化。

## 3. 实测扫描数据（v0.6 · 230 条，2026-10-27）

### 3.1 Noul 门槛扫描

| 门槛 | 覆盖率 | 区间判定一致率 | 通过区间实际可处理率 | 推到人工确认 |
| ---: | ---: | ---: | ---: | ---: |
| ≥ 0.50 | 73.9% | 90.4% | 92.9% | 26.1% |
| ≥ 0.55 | 73.0% | 90.4% | 93.5% | 27.0% |
| **≥ 0.60（当前）** | 71.3% | **89.6%** | 93.9% | 28.7% |
| ≥ 0.65（上一代） | 69.6% | 89.6% | 95.0% | 30.4% |
| ≥ 0.70 | 67.4% | 88.3% | 95.5% | 32.6% |
| ≥ 0.80 | 63.0% | 83.9% | 95.2% | 37.0% |
| ≥ 0.90 | 57.0% | 79.6% | 96.2% | 43.0% |

**两个结论**：

1. **0.60 维持采纳**（2026-10-26 业务采纳，v0.6 复扫维持）：v0.6 分布下 0.50–0.60 为
   89.6%–90.4% 一致率平台区（差异噪声级），0.60 以 -2.6pp 覆盖换 +1.0pp 通过内准确率
   （93.9% vs 92.9%），仍为膝点平衡解；结论在 v0.2/v0.3/v0.6 三代模型上方向一致。
2. **0.80 三代证伪**：v0.2 上一致率暴跌至 69.6%，v0.3 修复至 83.0%，v0.6 仍仅 83.9%——
   显著劣于 0.60–0.65 区间且覆盖仅 63.0%，保守代价过大。

### 3.2 Choice 门槛扫描（top-1 概率）

| 门槛 | 覆盖率 | 通过区间分类准确率 |
| ---: | ---: | ---: |
| ≥ 0.50 | 85.2% | 83.7% |
| **≥ 0.60（当前）** | 73.0% | 86.3% |
| ≥ 0.70 | 63.5% | 87.0% |
| ≥ 0.80 | 47.8% | 90.9% |
| ≥ 0.90 | 30.4% | 94.3% |

0.60 仍是膝点：再往上每牺牲 ~10pp 覆盖只换 ~2–5pp 区间准确率。**结论：choice 0.60 维持不变。**

### 3.3 端到端分流模拟（进对队列 / 进错队列 / 漏到人工）

| choice | noul | 完全自动正确 | 进错队列 | 漏处理/错放行 | 人工确认兑底 |
| ---: | ---: | ---: | ---: | ---: | ---: |
| 0.60 | **0.60（当前）** | 51.3% | 6.5% | 10.0% | 32.2% |
| 0.60 | 0.80 | 47.4% | 6.1% | 13.9% | 32.6% |
| 0.70 | 0.60 | 47.0% | 5.7% | 14.8% | 32.6% |
| 0.50 | 0.50 | 54.8% | 8.7% | 6.1% | 30.4% |
| 0.70 | 0.80 | 43.5% | 5.2% | 18.3% | 33.0% |

当前组合（0.60/0.60）：**51.3% 的消息全自动进对队列（历史新高）**，6.5% 进错队列，
10.0% 漏处理由待确认队列人工兑底（历史新低）——v0.3 同组合为 48.7%/6.1%/11.3%，
v0.6 以 +0.4pp 进错队列的代价换取全自动正确 +2.6pp、漏处理 -1.3pp。
若追求更高自动化（0.50/0.50）可到 54.8%，但进错队列升至 8.7%——不建议。

## 5. 重算流程（模型迭代 / 判据变更 / 评估集扩充后）

```powershell
cd backend
# 1. 回放评估集（http 模式复用运行中的服务；--local 进程内加载）
.venv\Scripts\python.exe evals\replay_eval.py            # 产出 reports/eval-report.json
# 2. 阈值扫描（读 eval-report.json 的逐条概率）
.venv\Scripts\python.exe evals\threshold_scan.py         # 产出 reports/threshold-scan.md
# 3. （可选）双引擎对比
.venv\Scripts\python.exe evals\ab_runner.py              # 产出 reports/ab-report.md
```

同步三处：`src/config/criteria.ts`（门槛常量）→
`src/data/calibration.ts`（校准页数据快照）→ 本文档扫描表。

**重要**：判据（criteria 措辞）或温度变更会改变概率分布的含义，任何一者变化后
**必须**重跑回放再谈门槛，否则门槛数字失去语义。

## 6. 已知限制与下一步（v0.6）

1. **L3 三代迭代收敛**：22 条直播中断类真值样本命中 13 条（59%）+ 2 条 L1 升格误报
   （ev-0129 麦克风太远 / ev-0137 标题写错时间，排序偏高由待确认队列人工兑底消化）；
   漏判 9 条中 7 条判 L2 仍进「优先协助」不漏处理、仅 2 条判 L1。
   v0.4→v0.5→v0.6 三轮实测证实跷跷板效应（TRAINING.md 7.5 实战案例二/三），
   最终以「撤掉 v0.5 过矫正对照」破局——单点补种子的收益已尽，进一步提升需真实弹幕回流扩数据。
2. **低置信区（choice 0.2–0.4）转为保守**：实际 46.7% 高于平均置信 36.2%（v0.3 期为
   过度自信 29.4% vs 35.8%）——方向反转但该区间仍被 0.60 门槛拦下进待确认，人工兑底不变。
3. **chat 边界噪声**：chat→feedback 收敛至 6 条（v0.3 为 10 条），新增 chat→spam 5 条
   （课程群询问/弹幕礼仪类被误判推广）；insufficient→technical 12 条成为最大错误源
   （指代不明 vs 环境差异的语义边界）——两类均待真实弹幕回流扩充；
   口径教训（chat 语义完整 = true）见 TRAINING.md 7.5。
4. **评估集规模**：230 条覆盖五类与四级影响；招投标场景迁移（v1.0）时需按新判据重建评估集并重扫本表。
